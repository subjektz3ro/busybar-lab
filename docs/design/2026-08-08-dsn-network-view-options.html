No—the current layout is not the best answer to “what is the DSN doing globally?” It spends scarce pixels on one friendly name and one contact-level receive-record digit per site. What the research says to protect

The useful lesson is not “use chart X.” It is to decide whether a glance should answer overview, identity, relation, change or history, then give that task a stable visual grammar.

Overview before detail

Shneiderman's information-seeking model starts with the whole collection, then selection and details. That supports Network → Instrument → Distance—and argues against making Network look like a complete snapshot when it is only one page. Original paper

Make the source hierarchy spatial

Treemaps use bounded area to reveal a hierarchy in limited space. DSN data already has one: network → site → dish/craft contact. A mosaic can make site load visible without adding another number. Original paper

Time can explain “zero”

LifeLines and horizon graphs show why compact, aligned histories help people notice duration, events and comparison. That suggests contact lifelines and site small-multiples—not a continuously decorative waveform. LifeLines · Horizon study

Glanceable means abstract and stable

Research on peripheral displays recommends matching expectations, simplifying to essentials, making states visibly distinct and keeping mappings consistent. That favors stable G/M/C positions and coarse, repeated RF marks over tiny changing legends. Berkeley report

Dashboards need a strong hierarchy

IBM's dashboard guidance puts the big-picture status first and gives the most important information the strongest contrast and area. On this bar, site totals and freshness outrank an unlabeled per-contact receive-record digit. Carbon guidance

Design at native resolution

Tidbyt's official pixel-display guidance says to author at the device's actual resolution, complete animation cycles, and expire stale time-sensitive content. BUSY Bar adds harsher LED gaps and contrast limits, so every option below stays mostly off and loops on fixed clocks. GIF guidance · Widget guidance

Never make colour carry truth alone

NASA human-interface guidance favors consistent, redundant coding and unambiguous feedback. Here, lane position establishes TX/RX, colour refines band, and freshness gets its own fixed edge grammar. That matters because X-band orange and feed-delay amber are easy to confuse when both appear as tiny moving lights. NASA HSI guidance

Source truth NASA itself frames DSN Now as a network overview with antenna selection for technical detail, and notes that one antenna can communicate with more than one spacecraft. NASA DSN Now

Recommendation: prototype Summary + Focus first

It corrects the actual comprehension failure without throwing away the full-name work, RF grammar, heartbeat or the three-view architecture. Network becomes the global answer; Instrument keeps exact stream records, power, rate, pointing and modes; Distance keeps the physical-separation story.

  1. Replace the naked right digit with permanent site totals: G1 M0 C4.
  2. Use one global contact order and show 2/5; never repeat a short site list to fill another site's pages.
  3. Keep one wide full-name marquee and long duplex lanes for the selected contact.
  4. Represent receive-record multiplicity as carrier marks; keep the exact count in Instrument.
  5. Keep source-triggered event cards and heartbeat independent of this layout.

Then test one bolder idea

Put the Focus-Lens Roster and Handoff Rails on the real bar for a week as alternate Network scenes. Focus-Lens best preserves “all five are here” while still honoring full names; Handoff Rails most strongly reveals a story that only live DSN snapshots can provide. The spaced LEDs—not this browser—should decide which one survives.
